# ADR-003：树标签的 dirty 语义、祖先传播与拼接顺序

## 状态

已接受。

## 背景

树标签插件需要让 `modified-star` 与 box 的 `(box)` 同时存在，且新增标签不能要求内核或渲染器识别标签类型。`modified-star` 还必须正确处理保存、编辑和撤销，状态不能放在模块级变量或 Shape 内核字段中。

## 决策

### 1. dirty 按内容判定，而不是按命令历史判定

每个 `modified-star` 装饰器实例用 `WeakMap<Shape, string>` 保存上次基线的普通 SVG 内容。`init/read` 建立初始基线，`save` 成功后建立新基线。渲染时当前内容与基线不同即显示 `*`。

因此，编辑后撤销到保存点时 `*` 消失；redo 再次出现。新建节点没有保存快照，创建后立即显示 `*`。这里比较的是内容，不是“是否执行过编辑命令”。

### 2. 子图形变化传播到祖先容器和 SVG 根行

容器快照包含完整子树，所以修改子图形会同时使其祖先容器和根节点 dirty。`tree <id>` 只显示所渲染子树内的标记；完整 `tree` 还在 `svg (WxH)` 行尾显示根标记。

### 3. 多个标签按插件注册顺序拼接

`DisplayView` 只按装饰器数组顺序执行 `flatMap`，再用单个空格拼接，不理解标签含义。默认装配中 box 先于 modified-star，因此同一行显示 `(box) *`。任一标签可独立启停。

### 4. 生命周期接口保持通用

`TreeDecorator` 提供可选的 `documentLoaded` 和 `documentSaved` 通知。内核只发送文档事件，不保存 dirty 集合，也没有 `modified-star` 条件分支。每个应用通过 `createModifiedStarPlugin()` 获得独立实例，避免跨应用共享状态。

## 后果

- 内容回到保存状态即清除标记，不要求历史栈向插件暴露命令事件。
- 快照依赖各 Shape 的普通 SVG 序列化；装饰器不修改文档。
- 新增纯展示标签无需再改内核或 DisplayView；需要文档生命周期的新标签复用同一组通用通知。
